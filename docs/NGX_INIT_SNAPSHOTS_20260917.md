# NGX initialization snapshots — 2026-09-17

## Owned search paths

Each D3D11/D3D12/Vulkan UpdateInitPaths previously cleared a shared string vector and allocated an unowned raw pointer array. Its entries referenced that vector's string storage, so another Init or GetFeatureCommonInfo could invalidate pointers still being passed to native code. Arrays also had no corresponding owner/release.

NgxPathSnapshot now owns both strings and the pointer array. Each adapter retains a shared immutable snapshot through its native/provider calls and nested delegated calls. Replacing the cached paths uses a short metadata lock and does not invalidate active snapshots; no lock is held during native calls. All 11 exported Init adapter sites retain their owner. The three internal proxy Init helpers and the separate DlssNr_Proxy caller also retain the owning result of GetFeatureCommonInfo. Both owning helper results are marked nodiscard.

Search ordering is unchanged: explicit overrides, Aurora path, caller paths, executable path and discovered runtime paths keep their previous positions. Vulkan's existing bad-length workaround remains. GetFeatureCommonInfo adds the selected DLSS directory only to its own snapshot, eliminating repeated append growth in the shared cache. The cache still means the most recently published search path list; this does not establish per-device search configuration or synchronize other Config/State fields.

32 local extracted-production checks pass: all three actual builders, representative actual Init adapter prefixes, GetFeatureCommonInfo, Unicode/spaces, override ordering, caller-buffer mutation, replacing the cache while an old owner remains, owner reclamation, nested delegated calls, exception unwind, empty lists and Vulkan's bad-length path. Four concurrent writers/readers publish and inspect 4,000 snapshots. Test SDK/Config/native boundaries are stand-ins, not a driver or GPU test. Existing shutdown extraction is adapted for the helper's owning return type; unrelated installer suites are not rerun.

Snapshots remain alive through synchronous Init calls. This does not promise indefinite pointer validity for a third-party implementation retaining caller arguments after Init returns. Shared application/project metadata, logger state and replacement-provider shutdown remain separate follow-ups. No installer, shader, SL1 or 6X change; no main merge or Release in this checkpoint.

## Application/project metadata follow-up — 2026-09-18

The next change replaces seven independently mutable State fields with NgxInitMetadata. Previously a second Init/UpdateFeature could modify strings while a native Init still consumed their c_str pointers, and a logger callback could be checked against one publication and invoked from another. Application id/data path/SDK version and project id/engine/version now publish as their respective groups; log callback/level/flags publish together. Writers preserve other groups and readers retain one immutable owner. Internal assignment/copy work holds a short mutex; native calls and application log callbacks run after releasing it.

All three internal native Init helpers retain one owner for every metadata argument through the complete call. FSR/XeSS adapters also capture once before their Init calls. Neural-rendering callers retain a temporary owner through the complete native call expression. Engine-only readers consume a snapshot instead of accessing a racing scalar. Original default values, generic-id overrides, search order and engine decisions remain unchanged. Duplicate SDK-version assignments are removed. Logging now copies the bounded spdlog payload into a terminated string before calling the NGX callback, rather than treating the view's data pointer as an unbounded C string.

39 new local checks compile the production header, actual D3D11/D3D12/Vulkan Init helpers, adapter publication statements and actual logging lambda. They cover borrowed-buffer mutation, retained old snapshots, grouped updates, reclamation, empty paths, native reentry replacing the entire metadata while old pointers are still in use, both project/application routes on all three APIs, log level filtering and bounded payloads. Three concurrent writers perform 6,000 grouped publications while another reader takes 6,000 snapshots. The affected 43 shutdown-routing checks pass after fixture adaptation. These are CPU/stand-in checks; full Windows DLL build validation is recorded below once complete.

This is memory ownership and grouped publication, not a per-device configuration registry. Separate application/project/path updates still describe the most recently published global state and can belong to different calls; per-device semantics and transactional commit after successful Init remain open. The logger snapshot owns its callback pointer value, not the code module supplying the callback. Existing spdlog callback-sink reentry behavior, Config/runtime-path optionals, replacement-provider shutdown and stale-handle generations remain separate boundaries. No GPU/game verification is inferred and no aurora synchronization is performed at this checkpoint.
