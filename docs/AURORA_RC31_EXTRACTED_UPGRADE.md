# RC3.1 巫师3更换解压位置后重装

2026-09-14。基线 `4b3bc458`，沿用 `aurora-rc3-installer-20260913`；不改核心渲染、SL1、6X，不合并 aurora。

## 实际原因

用户先在 `bin/x64_dx12` 解压旧包并安装，Remove 完成后把新包解压到游戏根目录。旧 DX12 `OptiScaler.dll` 是解压源文件，并未由安装器写入，因此 Remove 正确保留它；新包核心与旧文件 hash 不同。旧预检只有“同字节保留”或“有活动 ownership 才更新”两条路径，没有让用户安全处理解压遗留文件的入口。

现场新核心 SHA256 为 `B6476AEC651F6D4B5DC60D8595836A7168822446B8E6898BFA24398F8DA7CE70`，旧核心为 `234DBAC859D0423A8CCCC9FD3A39801888867745D101BE63F3067FFA83029711`。总清单仍是 Removed，DX11 的47条核心记录、DX12的1条Proxy记录都是 Restored。本次异常发生在全目标预检，尚未开始新的游戏文件部署；不是双入口发现或 Runtime 阶段失败。原始错误报告保存在本地资料工作区 `work/witcher-reinstall-20260914/`。

## 修复与保护边界

- 全部候选目录预检后收集未受管理、字节不同的核心/包内文件冲突，报告记录具体路径、旧hash、新hash。无冲突仍一键安装。
- 交互模式显示摘要；D查看全部路径，B显式同意备份并替换，Enter取消。未明确同意、非交互调用、非布尔确认结果都停止，保持原文件及Removed总清单。
- 同意只覆盖本次审阅的具体文件；写入前重新核对所有目标，防止审阅期间变化。复用已有原始备份校验、write-ahead journal、原子复制、完整部署自检。失败继续进入可恢复的 NeedsAttention，不能报告成功。
- Remove 对这类条目恢复校验过的原文件，不把原先手工解压的文件当作新增文件删除。更新后用户修改的文件保留。
- 未受管理的 Proxy 冲突、第三方 Proxy、受管文件被修改、损坏或缺失的活动日志/备份仍不能通过B绕过。不会放宽反作弊或候选筛选。配置不进入冲突替换，原生 Runtime 继续原安全流程；包内运行库副本与原生 Runtime 分开处理。
- 标题变为“RC3.1 · 重装修复版 20260914”。不会仅凭 OptiScaler 文件名或 PE OriginalFilename 自动认领旧文件。

## 当前现场使用

将新完整工具ZIP解压覆盖到本次新版完整包所在的《巫师3》根目录，保留全部OptiScaler目录、清单、备份及DLL。从根目录运行Aurora_Setup.bat，确认“重装修复版”标题、两个witcher3.exe/dxgi入口，按Enter；出现旧文件冲突时按D查看，按B备份更新。无需删除x64_dx12旧DLL或任何日志。

工具包不含核心DLL，必须配合完整新版发布包；仓库替换ZIP不能解压到游戏。不手工覆盖仍在活动清单管理下的游戏内工具，独立包可通过GameRoot指定游戏。
